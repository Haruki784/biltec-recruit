# チョク採テンプレートでページを作る手順

作業前に `CLAUDE.md` と `docs/parts-catalog.md` を読む。

## フェーズ1：デザインを読み、パーツを割り当てる（まだコーディングしない）

1. **Figmaを読む**（Figma MCP）
   - `get_metadata` でページとフレームの一覧を取り、PCとSPのトップフレームを特定する。
   - ページ全体を取ると応答が大きすぎて失敗する。`get_design_context` は**セクション単位のノード**で呼ぶ。
   - MCPがつながらない、または上限に達したとき：PCとSPのフレームを PNG で書き出して `_design/<page>/` に置いてもらう。セクションごとの切り出しはこちらで行う（ユーザーにセクションごとのスクショを何度も頼まない）。
2. **トークンを拾う**：色、フォント、見出しと本文のサイズ、角丸。`assets/settings.css` との違いを一覧にする（初回の案件、または初めて作るページのときだけ）。
3. **セクションごとの割り当て表を作る**。`_design/<page>/plan.md` に次の表を書く：

   | # | Figmaセクション（ノードID） | 使うパーツ | 判定 | メモ（変える点・画像） |
   |---|---|---|---|---|
   | 1 | MV (12:34) | （TOP用MV：新規） | 新規 | … |
   | 2 | 私たちについて | `president-message-typeB` | 流用 | 画像を差し替え |
   | 3 | 数字で見る | `number-typeA` | 流用＋調整 | 6項目 |

   判定は次の4つのどれか：
   - **流用**：見本のHTMLをそのまま使い、テキストと画像だけ差し替える
   - **流用＋調整**：ユーティリティclassの付け替えやトークンの変更で合わせる
   - **新type**：既存ブロックに `-typeX` を追加する
   - **新規**：新しいブロックを作る

   パーツ名は `docs/parts-catalog.md` に載っているものだけを使う。見本のないパーツ（chart、scroll など）はCSSを読んでから判断する。
4. **ユーザーに割り当て表を見せて確認をもらう。** 新type・新規の数が多いときは特にそう。確認が取れるまでフェーズ2に進まない。

## フェーズ2：コーディング

1. **トークン**：案件の色やフォントが決まっていれば `assets/settings.css` に反映する。Google Fonts の `@import` も差し替える。
2. **画像**：書き出し素材を `img/<page>/` に置く。SP用は `_sp` 接尾辞を付ける。可能なら webp にする。`width` と `height` を書く。
3. **テンプレート**：`CLAUDE.md` の「ページテンプレートの型」に沿って組む。
   - 流用するパーツは、見本ファイルの該当行からHTMLをコピーして差し替える。classの構造は変えない。
   - 余白は Figma の値に最も近い spacing 段階（.8 / 1.2 / 1.6 / 2.4 / 3.2 / 4 / 5.6 / 8 / 12rem）を選ぶ。合わない値だけパーツのCSSに書く。
   - SPでの差は、まず `-sp` 付きのユーティリティで対応する。
4. **新type・新規パーツ**：`add.css` の末尾に `/* <block>-typeX */` という見出しを付けて書く。ブロックのclass名で始まるセレクタだけを使い、SP用の `@media screen and (max-width: 768px)` は同じ見出しの中に置く。書いたら `docs/parts-catalog.md` に1行追記する。
5. **JS**：既存の機能（`.toggle`、`.tab`、カウントアップ、グラフ、目次）で足りるか先に確認する。足りなければ `add.js` に `init<機能名>()` として追加し、要素がなければ return する。Splide は enqueue 済み。
6. **リンク**：`home_url('/<slug>/')` で書く。ヘッダー、ドロワー、フッターのナビは `header.php` / `footer.php` ではなく `function/functions_menu.php` の `theme_menu_defaults()`（メニューの初期値）を案件のページ構成に合わせて更新する。公開後の変更は 外観 → カスタマイズ → メニュー で行う。

## フェーズ3：確認

- ローカルのWordPressで表示を確認する（ブラウザペインで開く）。PCは1440px、SPは375px（`resize_window`）。Figmaとセクションごとに比べる。
- 768px前後、991px前後、1920pxで崩れないかを見る。
- placehold.jp、`href=""`、Figmaの一時URLが残っていないかを grep で確かめる。
- 結果は、割り当て表に「実装済み／差分あり（内容）」を追記して報告する。
